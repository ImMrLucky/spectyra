In-app SDK integrations

Add Spectyra directly to your application’s LLM API layer. Spectyra helps reduce LLM cost by optimizing requests before they reach your provider, while keeping your provider keys inside your own app.

Recommended: install Spectyra where your LLM API calls happen — usually your backend.

Start with TypeScript / Node.js or Python. Other language SDKs are coming later (see bottom of page).

Quick start — TypeScript / Node.js

The production SDK is @spectyra/sdk. Use createSpectyra() once, then complete() with your existing OpenAI client and createOpenAIAdapter(). Spectyra optimizes locally, your code still calls OpenAI with your API key — there is no Spectyra proxy for inference.

Browser / frontend usage

Most apps should run Spectyra on the server. Do not put OpenAI, Anthropic, Groq, or other provider API keys in frontend bundles.

Use a browser build of the SDK only for:

  • Optional devtools overlay (savings / quota hints) when you already have a Spectyra credential in a dev environment — still keep provider calls on the server.
  • Sending client-safe usage summaries to your own API (no raw prompts unless you explicitly design for that).

Today’s SDK exposes createSpectyra({ devtools: { enabled: true } }) and spectyra.mountDevtools() for the floating panel in supported browser environments — not a separate @spectyra/sdk/browser package.

Never expose provider API keys in browser code. Keep LLM provider calls on your server whenever possible.

SDK functions — TypeScript (@spectyra/sdk)

Public surface today (names match the published package):

  • createSpectyra(config?) — returns a client with complete, run, observability helpers, and optional devtools mount.
  • spectyra.complete(input, adapter) — primary path. Pass your provider client (e.g. OpenAI) plus createOpenAIAdapter() (or Anthropic / Groq adapters). Returns { providerResult, report, … }.
  • spectyra.run(input, execute) — callback style: your function receives optimized messages and returns { result, text, usage }. Same privacy guarantees as complete().
  • spectyra.getSavingsSummary(), getSessionCostSummary(), getLastRun(), getQuotaStatus(), getEntitlementStatus() — session / overlay metrics.
  • spectyra.mountDevtools() — browser-only floating panel (returns unmount).
  • createOpenAIAdapter() / createAnthropicAdapter() / createGroqAdapter() — wire provider SDKs.

Not shipped yet: names like new Spectyra(), .optimize(), .estimate(), .flush(), or a separate SpectyraBrowser class. When we add higher-level wrappers, this page will be updated to match.

SDK functions — Python (spectyra)

Today’s published API centers on the Spectyra class and SpectyraConfig:

  • Spectyra(config) — pick mode="runtime" (HTTP to local runtime) or mode="embedded" (native FFI + your provider callback).
  • run_chat_runtime(...) — POST /v1/chat/run on the runtime; returns SpectyraRunResult (e.g. output, savings fields).
  • run_chat(...) — in runtime mode delegates to run_chat_runtime; in embedded mode runs the FFI pipeline then your call_provider.

Not in the Python package yet: optimize(), estimate(), track_usage(), get_savings(), flush() as separate helpers — use runtime responses and your own logging/analytics until those helpers exist.

Security notes

  • Install Spectyra on the backend where LLM calls already happen.
  • Keep provider API keys in environment variables or a secret manager — never in client-side source.
  • Use a Spectyra API key or license key only on servers (or tightly controlled dev tools), not as a substitute for locking down provider keys.
  • Avoid sending raw customer prompts to analytics unless you have an explicit, reviewed data path.
  • Cloud telemetry modes send aggregated / redacted payloads when configured — not your OpenAI secret.

Pricing, entitlements, and telemetry

With a Spectyra license key or Spectyra API key, the SDK can refresh entitlements and quota. When quota blocks optimization, Spectyra may pass through the request (no optimization) so your app keeps working — inspect report / getQuotaStatus().

FAQ / troubleshooting

Where should I install Spectyra?
On the service that already holds your provider credentials — typically your API server, not the browser.
Python snippet fails to connect
Ensure a Spectyra local runtime is listening at SPECTYRA_RUNTIME_URL (default http://127.0.0.1:4269) and that provider keys are configured there for runtime mode.
OpenClaw vs in-app SDK
OpenClaw uses @spectyra/local-companion and its dashboard. In-app integrations use @spectyra/sdk or Python spectyra inside your app. See OpenClaw & Local Companion.
Java, Go, or .NET?
Packages are planned / documented on GitHub; this page focuses on TypeScript and Python only for now.

Coming later

Java, Go, and .NET SDKs will be linked here with the same install-from-registry story when they are ready. This page stays focused on TypeScript and Python so onboarding stays simple.

Start with your backend

If your app already calls OpenAI, Anthropic, Groq, or another supported provider from a server route, you can usually add Spectyra by wrapping that one call with createSpectyra + complete() (TypeScript) or by routing through the runtime / embedded path (Python).

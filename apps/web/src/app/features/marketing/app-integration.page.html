Browser / frontend usage

Most apps should install Spectyra in the backend, not the browser.

Do not put OpenAI, Anthropic, Groq, or other provider API keys in frontend code.

Reasonable frontend uses:

  • Optional savings overlay in the browser when overlay: true or SPECTYRA_OVERLAY=true (non-production) — see Dev / QA overlay
  • Client-safe usage summaries to your own API
  • Local development visibility
  • Apps where the browser only calls your API, not the LLM provider directly
Never expose provider API keys or your private Spectyra API key in browser bundles. There is no separate SpectyraBrowser helper in the SDK today.

Dev / QA savings overlay

During development or QA, you can enable the browser floating panel to see token/cost rollups and the latest run — no raw prompts are shown by default.

Defaults are safe: in production, the overlay does not turn on from environment alone. Use explicit overlay: true or SPECTYRA_OVERLAY=true outside production, or set devtools: { enabled: true } to force the panel when debugging.

debug: true or SPECTYRA_DEBUG=true (non-production) prints one-line summaries to the console after each complete() — savings % / estimated USD, passthrough reason, or traceId only. No messages, keys, or Authorization headers.

SDK API (what exists today)

TypeScript — @spectyra/sdk

  • createSpectyra(config?) — creates the client (pass spectyraCloudApiKey / SPECTYRA_API_KEY for cloud entitlements and optional redacted telemetry).
  • spectyra.complete(input, adapter) — primary path; pass your provider client plus e.g. createOpenAIAdapter().
  • spectyra.run(input, execute) — callback style: you receive optimized messages and call the provider yourself.
  • spectyra.getSavingsSummary(), getSessionCostSummary(), getSessionStats(), getLastRun(), getLastRunSavings(), getQuotaStatus(), getEntitlementStatus() — observability helpers.
  • spectyra.refreshEntitlement() — manual entitlement refresh.
  • spectyra.mountDevtools() — mount the floating panel (browser); usually unnecessary if overlay auto-mounts.
  • spectyra.showOverlay() / hideOverlay() / toggleOverlay() — control visibility.
  • spectyra.getSavings() — summary + lastRun + lastRunSavings (no prompts).
  • spectyra.on("savings", listener) — numeric post-run events; returns unsubscribe.
  • config.environment, config.overlay, config.debug — see Dev / QA overlay.
  • createOpenAIAdapter() / createAnthropicAdapter() / createGroqAdapter() — provider wiring.

Python — spectyra

  • Spectyra(config) — supports environment, overlay, debug on SpectyraConfig (same gating rules as TypeScript for env-based flags).
  • run_chat_runtime(...) / run_chat(...) — same as before.
  • get_savings() — last run numeric snapshot (no prompt bodies).
  • on_savings(listener) — subscribe; returns unsubscribe callable.
  • show_overlay() / hide_overlay() / toggle_overlay() — no UI in Python; show_overlay prints a one-time note if overlay is requested.

Not in either SDK yet: a single optimize() / estimate() / flush() alias API — use TypeScript complete()/run() or Python run_chat* instead.

Security notes

  • Install Spectyra where LLM calls already happen (usually the server).
  • Keep provider API keys and your Spectyra API key server-side.
  • Use deployment secrets or backend config; local .env only for development.
  • Avoid sending raw prompts in browser telemetry unless you explicitly design for that.
  • Use public keys only in browser code when you have a deliberate, reviewed pattern.

Never: hardcode secrets; ship provider keys to the browser; or send raw customer data to analytics unless explicitly configured.

Passthrough & fallback behavior

  • runMode: "off" — Spectyra skips optimization; your adapter still runs (useful for killswitches).
  • runMode: "observe" — pipeline can run in observe semantics; check report.mode and docs for your version.
  • Quota / entitlements — when optimization is blocked, Spectyra can pass through so your app keeps working. Inspect report, licenseLimited, and getQuotaStatus().

FAQ

Where should I install Spectyra?
On the service that already holds your provider credentials — typically your API server, not the browser.
Do I need to clone the Spectyra repo?
No. Install @spectyra/sdk or spectyra from the package registry.
Python can’t connect to the runtime
Ensure a Spectyra runtime is listening at SPECTYRA_RUNTIME_URL (default http://127.0.0.1:4269) and that provider keys are configured there.
OpenClaw vs in-app SDK
OpenClaw uses the local companion skill. In-app uses @spectyra/sdk or Python inside your app. See OpenClaw & Local Companion.
Java, Go, or .NET?
Not on this page yet — use TypeScript or Python for now.
TypeScript vs Python — same features?
Core optimization today is centered on @spectyra/sdk complete()/run(). Python spectyra matches config flags (environment, overlay, debug), get_savings/on_savings, and safe debug logs; the browser overlay UI is TypeScript-only until a native Python UI exists.
